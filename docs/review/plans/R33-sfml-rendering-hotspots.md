# R33 — SFML rendering hotspots: миникарта и двойной обход сущностей

**Severity:** Medium (performance) · **Домен:** SFML rendering · **Roadmap:** P2

**Статус валидации:** ✅ Подтверждено по коду

## Проблема
Каждый кадр миникарта пересчитывается полным сканом тайлов (≈192×112), а список видимых сущностей перечисляется дважды за кадр. На больших картах/при росте числа сущностей это создаёт постоянную нагрузку на CPU в render-потоке, не связанную с реальными изменениями состояния, и ограничивает частоту кадров.

## Где в коде
- `src/SteelConveyorWar.Sfml/Ui/HudOverlay.cs:85-103` — миникарта: полный per-frame скан тайловой сетки (≈192×112) без кэша/dirty-регионов.
- `src/SteelConveyorWar.Sfml/Rendering/WorldRenderer.cs:44-55` — список видимых сущностей перечисляется дважды за кадр (двойной обход одной коллекции).

## План фикса
1. Миникарту рендерить в кэшированную текстуру; обновлять только dirty-регионы (изменённые тайлы/FoW), а не весь grid каждый кадр (связь с R16 dirty-regions).
2. Список видимых сущностей материализовать один раз за кадр и переиспользовать (единый обход вместо двух).
3. По возможности выносить пересчёт миникарты на изменение состояния/видимости, а не на каждый vsync.
4. Добавить лёгкий бенч/счётчик времени рендера, чтобы регрессии были заметны (связь с R22).

## Тесты
- Бенч: время рендера кадра при статичном состоянии близко к нулю по CPU (миникарта не пересчитывается без изменений).
- Тест корректности: dirty-обновление миникарты даёт тот же результат, что полный ре-рендер.
- Тест: сущности обходятся один раз за кадр (нет двойного перечисления).

## Definition of Done
- Миникарта обновляется инкрементально из кэша; видимые сущности обходятся однократно за кадр.

## Связанные замечания
R16 (FoW dirty-regions), R21 (декомпозиция SFML), R22 (perf-gate), R32 (TPS/history).

## Статус реализации: ✅ Частично реализовано / ⏸️ часть отложена 2026-08-11

⚠️ **Требуется прогон `dotnet build -c Release` + `dotnet test`** — VM был недоступен, код не компилировался и тесты не запускались. Изменения ниже нужно верифицировать сборкой и прогоном тестов.

### Что сделано (ограниченный, безопасный пункт — двойной обход сущностей)
- **Единый обход видимых сущностей** (`Sfml/Rendering/WorldRenderer.cs`): вместо материализации списка и **двух** проходов `.Where(...)` (сначала структуры, затем юниты) теперь один проход по `world.Entities` раскладывает видимые сущности в два списка (`structureDraws`/`unitDraws`) тернарником `(IsUnitDrawKind(kind) ? unitDraws : structureDraws).Add(entity)`. Порядок слоёв (структуры под юнитами) и порядок внутри слоя не изменились — отрисованный результат идентичен, но коллекция обходится один раз за кадр вместо двух + устранены две LINQ-аллокации.

### ⏸️ Отложено (кэш миникарты / dirty-регионы)
- **Миникарта в кэшированную текстуру с обновлением только dirty-регионов** (`Ui/HudOverlay.cs:85-103`) — **отложено**. Причина: это крупная работа, завязанная на инкрементальные dirty-регионы видимости из **R16** (тоже отложен: рерайт FoW с full-tick на событийный, чувствительный к state-hash), и её DoD требует бенчмарка рендера (R22) и прогона SFML-рантайма для подтверждения «около-нулевого CPU при статичном состоянии» и эквивалентности кэш↔полный ре-рендер. Ни собрать, ни прогнать, ни отбенчить в текущей среде нельзя. Вернуться вместе с R16.

### Отклонения / заметки
- Внутренности `DrawWorld` требуют `IRenderTarget` и не покрываются юнит-тестом в текущей среде; изменение по двойному обходу — строго behavior-preserving (тот же порядок отрисовки), проверяется чтением.
- DoD закрыт частично: «видимые сущности обходятся однократно за кадр» — сделано; «миникарта обновляется инкрементально из кэша» — отложено до R16.
